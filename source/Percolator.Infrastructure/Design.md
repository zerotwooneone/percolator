# Percolator.Infrastructure

Spec: [design-spec](../spec/design-spec.md)

## 1. Purpose and Layer Boundary

`Percolator.Infrastructure` is the portable, cross-platform (`net10.0`) technical adapter deployable. It realizes the outbound persistence, cryptographic math, wire serialization, in-memory pub/sub event bus, and network transport ports defined by the inner Domain and Application layers without introducing operating-system-specific P/Invoke locks (realizing [`DEP-INFRA-SEGREGATION-ROLE`](Requirements.md#1-segregation-role-and-boundary-constraints)).

- **In Scope:** Pre-unlock database vault & plausible-deniability header management, SQLCipher relational persistence & CQRS query projections, concrete cryptographic/ZK math engines, Protobuf wire serialization, gRPC/TLS streaming adapters, in-memory event bus technical adapter (`InMemoryEventBus`), portable file storage, and background maintenance workers.
- **Out of Scope:** Windows-specific kernel/CNG APIs (segregated into `Percolator.Infrastructure.Windows`), domain business rules, and UI reactive state.

---

## 2. Architectural Invariants and Encapsulation

1. **`INV-STAGE2-HOST-ISOLATION` (Two-Stage DI Host Isolation):** The pre-unlock bootstrap container (`IStage2HostFactory`) registers only Stage 1 vault unlock services. `PercolatorDbContext`, domain repositories, query services, event bus singletons, and background workers exist exclusively inside the child `IStage2Host` created *after* the database key is verified and schema migrations succeed. `#session-lock`
2. **`INV-ADAPTER-HYDRATION-BOUNDARY` (Internal-Only Domain Reconstitution & Protobuf Isolation):** Persistence adapters reconstitute domain aggregates via [`INV-INTERNAL-REHYDRATION`](../Percolator.Domain/Design.md#2-architectural-invariants-and-encapsulation) in `Percolator.Domain` and `Percolator.Apps.FileTransfer.Domain`. Compiled Protobuf classes and EF Core entities remain `internal` to infrastructure and never leak across port interfaces.
3. **`INV-VERTICAL-PERSISTENCE-SLICES` (Vertical Persistence Slices):** Each feature slice co-locates its EF Core entity mapping, aggregate write repository, and zero-hydration SQL read-model query service (realizing [`INV-CQRS-SEPARATION`](../Percolator.Application/Design.md#2-architectural-invariants-and-encapsulation)).

## 3. Key Technical Design Choices

1. **`DEC-PINNED-SQLITE-KEY` (Zero OS Keyring Persistence & Pinned Master Key + Native `sqlite3_key`):**
   - *Design Choice:* The SQLCipher master key (`IMasterKeyHandle`) is never stored in OS credential vaults (DPAPI/Keychain) or passed in connection strings (realizing [`DEP-INFRA-VAULT-ENCRYPTION`](Requirements.md#2-allocated-responsibilities)). It is unwrapped in memory from `percolator.header` during Stage 1 unlock, held in a pinned byte array (`GC.AllocateArray<byte>(..., pinned: true)`), applied to SQLite connections via native C-API `SQLitePCL.raw.sqlite3_key` inside an EF Core connection interceptor, and cryptographically zeroized upon session lock or disposal. `#session-lock`
   - *Rejected Alternative:* Passing hex keys via connection strings (which leaves uncollectable immutable `string` copies on the managed heap) or persisting keys in OS keyrings.
2. **`DEC-TWIN-SLOT-DURESS-HEADER` (Constant-Size Twin-Slot Header for Plausible Deniability):**
   - The vault header always serializes both a master key slot and a duress slot; when no duress passphrase is set, the duress slot is populated with CSPRNG noise so file size and entropy are indistinguishable from an active duress configuration. Entering the duress passphrase cryptographically shreds the vault before initializing a clean decoy database.
3. **`DEC-BIG-ENDIAN-BLOB-UUID` (RFC 4122 Big-Endian `BLOB(16)` UUID Storage):**
   - All `[GuidId]` primary and foreign keys are stored as 16-byte big-endian `BLOB` columns (`Guid.ToByteArray(bigEndian: true)`), cutting index footprint in half compared to text UUIDs while preserving lexicographical B-Tree sort order for sequential UUIDv7 keys (per [`DEC-BIFURCATED-UUID`](../Percolator.SourceGenerators/Design.md#3-key-technical-design-choices)).
4. **`DEC-SIGNAL-INTEROP-QUARANTINE` (Quarantined Cryptographic SOUP Adapter & Span Zeroization):**
   - *Design Choice:* Quarantines `Signal.Interop` and native `signal_shim.dll` ([`SOUP-SIGNAL-ED25519-KEYGEN`](../soup/signal-interop.md#31-active-functional--capacity-envelope), [`SOUP-SIGNAL-ED25519-SIGN`](../soup/signal-interop.md#31-active-functional--capacity-envelope), [`SOUP-SIGNAL-ED25519-VERIFY`](../soup/signal-interop.md#31-active-functional--capacity-envelope), [`SOUP-SIGNAL-ZKGROUP-CREDENTIALS`](../soup/signal-interop.md#31-active-functional--capacity-envelope)) strictly within `SignalCryptoEngine` and `ZkgroupCryptographyService`, realizing [`DEP-INFRA-SEALED-SENDER-CRYPTO`](Requirements.md#2-allocated-responsibilities) and [`DEP-INFRA-ZKGROUP-CREDENTIALS`](Requirements.md#2-allocated-responsibilities) (implementing system decision [`DEC-SIGNAL-INTEROP-ADOPTION`](../DecisionRegister.md#2-cryptographic-protocol-and-security-decisions)). The adapters translate all unmanaged return codes into value-type `DomainResult<T>` failures ([`FACT-CLR-EXCEPTION-HOTPATH-OVERHEAD`](../facts/platform-runtime.md#2-axioms-and-platform-invariants)), validate input span non-emptiness before native boundary transitions ([`DEP-INFRA-DEFENSIVE-SPAN-VALIDATION`](Requirements.md#3-public-contract-invariants)), enforce stack allocation for ephemeral buffers, and invoke `CryptographicOperations.ZeroMemory` immediately following operation completion ([`DEP-INFRA-VOLATILE-ZEROIZATION`](Requirements.md#3-public-contract-invariants), [`FACT-DEAD-STORE-ELIMINATION`](../facts/platform-runtime.md#2-axioms-and-platform-invariants)).
   - *Rejected Alternative:* Direct invocation of native P/Invokes from domain entities or throwing native interop exceptions across application boundaries.
5. **`DEC-MEDIA-EXIF-SCRUBBING` (Media EXIF and Metadata Sanitization Pipeline):**
   - *Design Choice:* Outbound images and media streams processed via `StreamingAesGcmCryptoService` are parsed and stripped of EXIF, IPTC, XMP, GPS coordinates, and camera device serials prior to 64 KB block chunking and AES-256-GCM encryption, realizing [`DEP-INFRA-MEDIA-METADATA-SANITIZATION`](Requirements.md#2-allocated-responsibilities) and [`SYS-MEDIA-METADATA-SANITIZATION`](../SystemRequirements.md#2-security-privacy-and-risk-control-invariants) (mitigating [`HAZ-PAYLOAD-METADATA-EXPOSURE`](../RiskRegister.md#1-cryptographic-identity-and-privacy-hazards); implementing system decision [`DEC-CHUNKED-STREAM-AEAD-TRANSFER`](../DecisionRegister.md#1-architectural-and-structural-decisions)). Media and blob transfers enforce a 100 MB single-stream ceiling and a 5 GB local cache quota ceiling, aborting oversized transfers with value-type `DomainResult.Failure` without process termination (realizing [`DEP-INFRA-LOCAL-BLOB-STORE`](Requirements.md#2-allocated-responsibilities)).
   - *Rejected Alternative:* Performing metadata scrubbing client-side in UI components (which risks omission across different client frontends or background attachments) or transmitting raw media files without sanitization.
6. **`DEC-SWARM-HEADER-VALIDATION` (Swarm Transport Frame Bounded Header Validation & Root Containment):**
   - *Design Choice:* In `TcpMultiStreamPool` and `PortableDesktopFileStore`, validate fixed 5-byte frame header lengths (`<= 262,144 B`) before allocating receive buffers to prevent remote heap exhaustion, enforce a 5-second handshake timeout against Slowloris socket holding, and verify that all manifest and chunk file allocations stay strictly within the canonical root directory (`Path.GetFullPath(resolvedPath).StartsWith(canonicalRoot)`) rejecting traversal sequences (`..`), leading slashes, null bytes, or OS reserved device names (realizing [`DEP-INFRA-PORTABLE-FILE-STORAGE`](Requirements.md#2-allocated-responsibilities) and [`SYS-PATH-TRAVERSAL-DEFENSE`](../SystemRequirements.md#2-security-privacy-and-risk-control-invariants); implementing system decision [`DEC-CHUNKED-STREAM-AEAD-TRANSFER`](../DecisionRegister.md#1-architectural-and-structural-decisions); mitigating [`HAZ-PATH-TRAVERSAL-OVERWRITE`](../RiskRegister.md#2-endpoint-availability-and-integrity-hazards) and [`HAZ-INGRESS-RESOURCE-EXHAUSTION`](../RiskRegister.md#2-endpoint-availability-and-integrity-hazards)).
   - *Rejected Alternative:* Dynamically allocating receive buffers based on untrusted 4-byte stream length headers without bounds checking (vulnerable to multi-gigabyte memory exhaustion OOM) or writing directly to relative manifest paths without canonical path validation.
7. **`DEC-NO-DOUBLE-ENCRYPTION` (Holistic SQLCipher At-Rest Vault Protection):**
   - *Design Choice:* SQLCipher transparently encrypts all pages, tables, indices, and temporary files with AES-256 under the Stage 1 master key. Sensitive payloads, ratchet states, and cryptographic keys (e.g., `chat_attachments.encryption_key`) are intentionally stored as native `BLOB` columns directly inside SQLCipher without redundant column-level double-encryption (`AesGcmValueConverter`).
   - *Rejected Alternative:* Applying application-layer AES-GCM encryption on top of SQLCipher page encryption, which wastes CPU cycles and adds per-column nonce/tag overhead.
8. **`DEC-RELATIONAL-OVER-JSON` (Relational Schema Normalization over JSON Blobs):**
   - *Design Choice:* Domain aggregate components (mentions, attachments, link previews) are mapped to normalized relational tables and first-class columns rather than serialized JSON blobs, preserving referential integrity, database indexing, and efficient keyset CQRS queries.
   - *Rejected Alternative:* Storing structured domain collections in `*_json` text columns.
9. **`DEC-BOUNDED-CHANNEL-EVENT-BUS` (Non-Blocking Fault Pipeline & Lock-Free Concurrent Dispatch):**
   - *Design Choice:* `InMemoryEventBus` realizes [`INV-APP-EVENT-BUS-DECOUPLING`](../Percolator.Application/Design.md#2-architectural-invariants-and-encapsulation) via CAS updates on immutable list snapshots within a concurrent dictionary for lock-free subscription registration, caches the type hierarchy to prevent hot-path reflection, fast-paths zero-subscriber events synchronously, and streams subscriber exceptions into a bounded `Channel<EventDispatchError>` (capacity 1,000, `DropOldest`) processed by a background worker task. This guarantees $O(1)$ non-blocking fault recording without publisher latency.
   - *Rejected Alternative:* Synchronous invocation of fault handlers on the publisher's thread (which induces cumulative Head-of-Line blocking if an error handler is slow) or unbounded thread pool task spawning (`Task.WhenAll`) which risks thread pool starvation under event bursts.
