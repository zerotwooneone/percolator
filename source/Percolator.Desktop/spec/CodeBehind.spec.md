# Avalonia Code-Behind Specification (`CodeBehind.spec.md`)

This specification governs all C# code-behind files (`*.axaml.cs`) paired with Avalonia XAML views—including `Window`, `UserControl`, and `TemplatedControl` across `Percolator.Desktop`.

Any file governed by this specification MUST include this header comment on line 1:
```csharp
// SPECIFICATION GOVERNANCE: Read Percolator.Desktop/spec/CodeBehind.spec.md before modifying this file.
```

---

## 1. Quick Rules & Invariants

| ID | Category | MUST DO (Mandatory) | MUST NOT DO (Strictly Prohibited) |
| :-: | :--- | :--- | :--- |
| **[CB-001]** | **Logic & Purity** | Handle imperative view mechanics only (focus, layout adaptation, visual transitions, OS window lifecycle hooks). | MUST NOT contain business logic, domain mutations, database calls, or network operations. |
| **[CB-002]** | **Dependency Injection** | Receive ViewModels via constructor injection (`public MainWindow(MainWindowViewModel vm)`) or instantiation parameter. Parameterless constructors are permitted ONLY for XAML loader/previewer support (`public MainWindow() : this(null!)`). | MUST NOT instantiate ViewModels directly in code-behind (`DataContext = new MainWindowViewModel()`). MUST NOT access `App.Services` or `IServiceProvider` as a service locator. |
| **[CB-003]** | **Focus & Dimensions** | Use the routed `Loaded` event on `Control` for keyboard focus (`control.Focus()`), animations, and layout measurement. | MUST NOT call `.Focus()` or query `.Bounds` in `AttachedToVisualTree` (fires before layout; bounds are zero and templates unmaterialized). |
| **[CB-004]** | **Lifecycle Pairing** | MUST pair every subscription in `Loaded` with a teardown in `Unloaded`. MUST pair every subscription in `AttachedToVisualTree` with a teardown in `DetachedFromVisualTree`. | MUST NOT leave subscriptions active on detached controls. Subscriptions MUST be idempotent to prevent duplicate handlers when controls re-attach in tabs or virtualized panels. |
| **[CB-005]** | **Template Parts** | Query and wire child controls in `TemplatedControl` exclusively inside `OnApplyTemplate(TemplateAppliedEventArgs e)` using `e.NameScope.Find<T>("PART_...")`. | MUST NOT query template parts in constructors, `AttachedToVisualTree`, or `Loaded`. |
| **[CB-006]** | **Control References** | Access named XAML elements (`x:Name="MyInput"`) via the strongly typed fields generated by `Avalonia.NameGenerator` (`this.MyInput`). | MUST NOT use legacy string lookups (`this.FindControl<T>("MyInput")` or `this.Get<T>("MyInput")`) for statically declared XAML elements. |
| **[CB-007]** | **Platform Services** | Obtain windowing and platform services (clipboard, file pickers, insets) via `TopLevel.GetTopLevel(this)`. Modal dialogs and user confirmations MUST be surfaced exclusively through an injected application-level dialog service invoked from ViewModels. | MUST NOT construct, configure, or display modal dialogs in code-behind. MUST NOT pass ViewModels to `TopLevel.GetTopLevel()`. MUST NOT query `TopLevel.GetTopLevel(this)` before attachment (returns `null`). |
| **[CB-008]** | **Responsive Layout** | Adjust view-only properties (`SplitView.DisplayMode`, `Classes.Set()`) inside size-change handlers. | MUST NOT pump raw pixel coordinates, window dimensions, or `SizeChangedEventArgs` into ViewModels. |

## 2. Common AI Traps to Avoid

1. **The `AttachedToVisualTree` Focus Trap ([CB-003])**:
   * *Trap*: Registering `AttachedToVisualTree += (_, _) => PasswordInput.Focus();`. In Avalonia 11, `AttachedToVisualTree` fires before layout (`Measure`/`Arrange`) and before template materialization; `Bounds` are `0, 0` and focus will fail or behave erratically. Moreover, `Window` is a visual root and does not fire `AttachedToVisualTree` onto a parent tree.
   * *Fix*: Always use `Loaded += (_, _) => PasswordInput.Focus();`.
2. **The Virtualization / Tab Re-Attachment Leak Trap ([CB-004])**:
   * *Trap*: Registering event handlers or reactive subscriptions inside `Loaded` or `AttachedToVisualTree` without deregistering them in `Unloaded` or `DetachedFromVisualTree`. Controls hosted in tabs, flyouts, or virtualized lists (`ListBox`, `ItemsRepeater`) attach and detach repeatedly, causing duplicated event handlers and memory leaks.
   * *Fix*: Store subscriptions in a `CompositeDisposable` and clear them on `Unloaded` / `DetachedFromVisualTree`.
3. **The Parameterless Constructor ViewModel Instantiation Trap ([CB-002])**:
   * *Trap*: Writing `public MainWindow() { InitializeComponent(); DataContext = new MainWindowViewModel(); }`. This bypasses DI and prevents test isolation.
   * *Fix*: Inject the ViewModel via constructor injection, or leave the parameterless constructor strictly for previewer initialization.
4. **The Obsolete `FindControl<T>` Trap ([CB-006])**:
   * *Trap*: Calling `this.FindControl<TextBox>("SearchBox")` in Avalonia 11+.
   * *Fix*: Directly access the generated typed field `this.SearchBox`.
5. **The Service Locator Ingress Trap ([CB-002])**:
   * *Trap*: Accessing `((App)Application.Current).Host.Services.GetRequiredService<T>()` inside code-behind event handlers.
   * *Fix*: Inject required UI coordinators or services via constructor parameters.

## 3. Micro-Diff Examples: Bad vs. Good

### 3.1 Focus Management & Lifecycle Pairing ([CB-003], [CB-004])
```csharp
// ❌ BAD: Using AttachedToVisualTree for focus; no cleanup; bounds unarranged
public partial class VaultUnlockView : UserControl
{
    public VaultUnlockView()
    {
        InitializeComponent();
        AttachedToVisualTree += (_, _) => PasswordInput.Focus(); // VIOLATION: Fires before layout!
    }
}

// ✅ GOOD: Using Loaded with paired Unloaded lifecycle cleanup
public partial class VaultUnlockView : UserControl
{
    private IDisposable? _disposables;

    public VaultUnlockView()
    {
        InitializeComponent();
        Loaded += OnLoaded;
        Unloaded += OnUnloaded;
    }

    private void OnLoaded(object? sender, RoutedEventArgs e)
    {
        // Focus is guaranteed to succeed after layout and template application
        PasswordInput.Focus();
    }

    private void OnUnloaded(object? sender, RoutedEventArgs e)
    {
        _disposables?.Dispose();
        _disposables = null;
    }
}
```

### 3.2 Constructor Injection & DataContext ([CB-002])
```csharp
// ❌ BAD: Parameterless constructor instantiating its own ViewModel bypasses DI
public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
        DataContext = new MainWindowViewModel(); // VIOLATION: Bypasses DI!
    }
}

// ✅ GOOD: Constructor injection with previewer fallback
public partial class MainWindow : Window
{
    public MainWindow()
    {
        InitializeComponent();
    }

    public MainWindow(MainWindowViewModel viewModel) : this()
    {
        DataContext = viewModel ?? throw new ArgumentNullException(nameof(viewModel));
    }
}
```

### 3.3 Responsive Layout Adaptation (View-Only Mechanics) ([CB-008])
```csharp
// ❌ BAD: Pumping raw pixels into the ViewModel
private void Window_SizeChanged(object? sender, SizeChangedEventArgs e)
{
    if (DataContext is MainWindowViewModel vm)
    {
        vm.CurrentWidth = e.NewSize.Width; // VIOLATION: Pollutes ViewModel with pixels!
    }
}

// ✅ GOOD: Adjusting view-layer control properties directly in code-behind
private void Window_SizeChanged(object? sender, SizeChangedEventArgs e)
{
    if (InspectorSplitView != null)
    {
        InspectorSplitView.DisplayMode = e.NewSize.Width < 1000 
            ? SplitViewDisplayMode.Overlay 
            : SplitViewDisplayMode.Inline;
    }
}
```

### 3.4 Templated Control Part Resolution ([CB-005])
```csharp
// ❌ BAD: Querying template parts in constructor or Loaded
public class CustomDrawer : TemplatedControl
{
    public CustomDrawer()
    {
        // VIOLATION: Template is not yet applied; returns null!
        var button = this.FindControl<Button>("PART_CloseButton");
    }
}

// ✅ GOOD: Resolving template parts in OnApplyTemplate
public class CustomDrawer : TemplatedControl
{
    private Button? _closeButton;

    protected override void OnApplyTemplate(TemplateAppliedEventArgs e)
    {
        base.OnApplyTemplate(e);

        if (_closeButton != null)
        {
            _closeButton.Click -= OnCloseButtonClicked;
        }

        _closeButton = e.NameScope.Find<Button>("PART_CloseButton");

        if (_closeButton != null)
        {
            _closeButton.Click += OnCloseButtonClicked;
        }
    }

    private void OnCloseButtonClicked(object? sender, RoutedEventArgs e)
    {
        // View-only drawer collapse
    }
}
```

## 4. Citations & Verified Sources

* **Avalonia Control Lifecycle**: [Avalonia Documentation – Control Lifecycle](https://docs.avaloniaui.net/docs/concepts/lifecycle). Governs `Initialized`, `AttachedToVisualTree`, `ApplyTemplate`, `Loaded`, `Unloaded`, and `DetachedFromVisualTree` event sequence and layout guarantees.
* **Avalonia Code-Behind Principles**: [Avalonia Documentation – Code-Behind](https://docs.avaloniaui.net/docs/basics/user-interface/code-behind). Details the separation between declarative XAML and imperative view mechanics.
* **Avalonia TopLevel Architecture**: [Avalonia Documentation – TopLevel](https://docs.avaloniaui.net/docs/concepts/toplevel). Specifies `TopLevel.GetTopLevel(Visual)` for platform services (clipboard, file pickers, insets) and visual roots.
* **Avalonia Templated Controls**: [Avalonia Documentation – Custom Controls](https://docs.avaloniaui.net/docs/guides/custom-controls/how-to-create-templated-controls). Specifies the `OnApplyTemplate(TemplateAppliedEventArgs)` contract for template part resolution.
* **Avalonia Name Generator**: [Avalonia.NameGenerator Repository](https://github.com/AvaloniaUI/Avalonia.NameGenerator). Documents source generation of strongly typed fields for named XAML controls, superseding runtime `FindControl<T>` lookups.
* **Microsoft MVVM Clean Architecture Guidelines**: [Clean Architecture & MVVM Boundaries](https://learn.microsoft.com/en-us/dotnet/architecture/maui/mvvm). Prohibits business and domain operations in the UI layer.
