# R3 Reactive Extensions Specification (`R3.spec.md`)

This specification governs all reactive pipelines, asynchronous event handling, and collection synchronization across `Percolator.Desktop` using **R3 (v1.3.1)**, **R3Extensions.Avalonia (v1.3.1)**, and **ObservableCollections.R3 (v3.3.4)**.

Any file utilizing R3 observables, properties, or collections MUST declare compliance on line 1:
```csharp
// SPECIFICATION GOVERNANCE: Read Percolator.Desktop/spec/R3.spec.md before modifying this file.
```

## 1. Quick Rules & Invariants

| ID | Category | MUST DO (Mandatory) | MUST NOT DO (Strictly Prohibited) |
| :-: | :--- | :--- | :--- |
| **[R3-001]** | **Platform Setup** | Call `.UseR3()` in `Program.cs` `AppBuilder` and register `ObservableSystem.RegisterUnhandledExceptionHandler` in `App.axaml.cs`. | MUST NOT omit `UseR3()`; time and frame providers will default to thread pool instead of Avalonia Dispatcher, causing UI race conditions. |
| **[R3-002]** | **XAML Value Binding** | In XAML bindings targeting a `BindableReactiveProperty<T>`, bind explicitly to `.Value`: `{Binding SearchQuery.Value, Mode=TwoWay}`. | MUST NOT bind directly to `{Binding SearchQuery}` (binds to the wrapper object, rendering type name string). |
| **[R3-003]** | **UI Notification Contract** | Use `BindableReactiveProperty<T>` for UI-bound reactive properties. Standard `ReactiveProperty<T>` does not implement `INotifyPropertyChanged`. | MUST NOT bind raw `ReactiveProperty<T>` or `Subject<T>` directly to Avalonia controls without converting via `.ToBindableReactiveProperty()`. |
| **[R3-004]** | **Property Observation** | Use `this.ObservePropertyChanged(x => x.Prop)` for `INotifyPropertyChanged` classes. For nested paths, pass chained lambdas: `ObservePropertyChanged(x => x.A, a => a.B)`. | MUST NOT call `ObserveProperty` (legacy method from runceel library; does not exist in R3). MUST NOT use single chained expressions `x => x.A.B` (cannot be parsed by `[CallerArgumentExpression]`). |
| **[R3-005]** | **Disposable Lifetime (`ref Bag`)** | Anchor every observable subscription with `.AddTo(ref Bag)` (`DisposableBag` is a value-type `struct`). | MUST NOT pass `Bag` by value (`.AddTo(Bag)` passes a copy, discarding registrations and leaking memory). |
| **[R3-006]** | **Property Disposal** | Add `BindableReactiveProperty` to `ref Bag`: `Prop = expr.ToBindableReactiveProperty().AddTo(ref Bag)`. | MUST NOT leave `BindableReactiveProperty` un-disposed; its internal source subscription will leak. |
| **[R3-007]** | **Non-Terminal Error Contract** | Understand that R3 uses `OnErrorResume` (non-terminating). Streams stay alive on exception unless `.OnErrorResumeAsFailure()` is explicitly appended. | MUST NOT assume an unhandled exception terminates an R3 stream. |
| **[R3-008]** | **Collection Synchronization** | Maintain collections in free-threaded `ObservableList<T>`, project via `.CreateView(...)`, and bind via `.ToNotifyCollectionChanged(...)`. | MUST NOT expose raw `ObservableCollection<T>` across threads or mutate UI-bound lists from background threads. |
| **[R3-009]** | **Projected Item Disposal** | Always dispose removed item ViewModels: `view.ObserveRemove().Subscribe(e => e.Value.View.Dispose()).AddTo(ref Bag)`. | MUST NOT drop removed items from projected views without disposing child subscriptions. |
| **[R3-010]** | **Async Concurrency & Cancellation** | Use `SelectAwait(async (x, ct) => ..., AwaitOperation)` with explicit `Drop`, `Switch`, or `Sequential`. Forward the `CancellationToken` (`ct`) to all awaited tasks. | MUST NOT write fire-and-forget `async void` inside `.Subscribe(...)`. MUST NOT ignore the `ct` parameter in `SelectAwait` (breaks `AwaitOperation.Switch` cancellation). |
| **[R3-011]** | **UI Thread Marshaling** | Append `.ObserveOnUIThread()` to reactive pipelines that originate from background threads or network sockets before writing to UI-bound properties. | MUST NOT mutate UI properties or UI collections directly from background worker threads. |
| **[R3-012]** | **Deterministic Time Testing** | Pass injected `TimeProvider` (or `FakeTimeProvider`) to time-based operators (`Debounce`, `Throttle`, `Interval`). | MUST NOT use unparameterized time operators that default to system clocks in ViewModel logic. |

## 2. Common AI Traps to Avoid

1. **The Missing `ref` in `DisposableBag` Trap ([R3-005])**:
   * *Trap*: Writing `observable.Subscribe(...).AddTo(Bag);` (omitting `ref`).
   * *Mechanism*: `DisposableBag` is a high-performance value-type struct. Calling without `ref` passes a copy; the subscription is added to a temporary copy and discarded, causing permanent memory leaks.
   * *Fix*: Always write `.AddTo(ref Bag)`.
2. **The Missing `.Value` in XAML Binding Trap ([R3-002])**:
   * *Trap*: `<TextBox Text="{Binding SearchText, Mode=TwoWay}" />` where `SearchText` is `BindableReactiveProperty<string>`.
   * *Consequence*: XAML binds to the `BindableReactiveProperty` object itself, displaying `R3.BindableReactiveProperty`1[System.String]` in the input field.
   * *Fix*: Always write `{Binding SearchText.Value, Mode=TwoWay}`.
3. **The `ReactiveProperty` vs `BindableReactiveProperty` Trap ([R3-003])**:
   * *Trap*: Exposing `ReactiveProperty<T>` to XAML and wondering why two-way bindings never update the UI.
   * *Mechanism*: R3 split `ReactiveProperty` (lightweight push-based) and `BindableReactiveProperty` (implements `INotifyPropertyChanged`).
   * *Fix*: Always expose `BindableReactiveProperty<T>` to XAML.
4. **The `ObserveProperty` Hallucination Trap ([R3-004])**:
   * *Trap*: Writing `this.ObserveProperty(x => x.MyProperty)`.
   * *Mechanism*: `ObserveProperty` belongs to the legacy `ReactiveProperty` library. R3 uses **`ObservePropertyChanged`**, which leverages C# 10 `[CallerArgumentExpression]` for zero-allocation property name resolution.
   * *Fix*: Write `this.ObservePropertyChanged(x => x.MyProperty)`.
5. **The Dropped `CancellationToken` in `SelectAwait` Trap ([R3-010])**:
   * *Trap*: Writing `.SelectAwait(async (q, ct) => await _searchService.QueryAsync(q), AwaitOperation.Switch)`.
   * *Consequence*: Because `ct` was not passed to `QueryAsync(q, ct)`, the in-flight HTTP/database query cannot be canceled when a new character is typed. The previous slow query finishes and overwrites newer search results!
   * *Fix*: Always forward `ct`: `await _searchService.QueryAsync(q, ct)`.

## 3. Micro-Diff Examples: Bad vs. Good

### 3.1 Subscriptions & Struct Lifetimes ([R3-005])
```csharp
// ❌ BAD: Omitting 'ref' mutates a copy; subscription leaks permanently!
_chatService.MessageReceived
    .Subscribe(msg => AddMessage(msg))
    .AddTo(Bag); // VIOLATION: struct copy!

// ✅ GOOD: 'ref Bag' guarantees registration into the ViewModel's lifecycle
_chatService.MessageReceived
    .Subscribe(msg => AddMessage(msg))
    .AddTo(ref Bag);
```

### 3.2 Property Observation (`INotifyPropertyChanged`) ([R3-004])
```csharp
// ❌ BAD: Legacy method call that fails compilation in R3
this.ObserveProperty(x => x.WindowWidth)
    .Subscribe(w => HandleResize(w));

// ✅ GOOD: Native R3 zero-allocation property observation
this.ObservePropertyChanged(x => x.WindowWidth)
    .Subscribe(w => HandleResize(w))
    .AddTo(ref Bag);
```

### 3.3 Nested Property Observation ([R3-004])
```csharp
// ❌ BAD: R3 cannot parse nested expressions in a single lambda
this.ObservePropertyChanged(x => x.ActiveSession.RemotePeer.DisplayName);

// ✅ GOOD: Chained lambdas for nested property paths in R3
this.ObservePropertyChanged(
    x => x.ActiveSession,
    s => s.RemotePeer,
    p => p.DisplayName)
    .Subscribe(name => UpdateTitle(name))
    .AddTo(ref Bag);
```

### 3.4 Asynchronous Stream Handling (`SelectAwait`) ([R3-010], [R3-011])
```csharp
// ❌ BAD: Fire-and-forget async void inside Subscribe has no concurrency guard or cancellation
_searchQuery.Subscribe(async query =>
{
    var results = await _searchService.QueryAsync(query); // Race conditions on fast typing!
    Display(results);
});

// ✅ GOOD: AwaitOperation.Switch cancels in-flight queries and marshals to UI thread
_searchQuery
    .Debounce(TimeSpan.FromMilliseconds(200), _timeProvider)
    .SelectAwait(async (query, ct) => await _searchService.QueryAsync(query, ct), AwaitOperation.Switch)
    .ObserveOnUIThread()
    .Subscribe(results => Display(results))
    .AddTo(ref Bag);
```

### 3.5 Collection Projections & Disposal ([R3-008], [R3-009])
```csharp
// ❌ BAD: Projecting models without observing removal leaks child ViewModels
_syncView = models.CreateView(m => new PeerItemViewModel(m));
Peers = _syncView.ToNotifyCollectionChanged();

// ✅ GOOD: Explicit removal observation guarantees child ViewModel disposal
_syncView = models.CreateView(m => new PeerItemViewModel(m));
_syncView.ObserveRemove()
    .Subscribe(e => e.Value.View.Dispose())
    .AddTo(ref Bag);
Peers = _syncView.ToNotifyCollectionChanged(SynchronizationContextCollectionEventDispatcher.Current);
Bag.Add(_syncView);
Bag.Add(Peers);
```

## 4. `AwaitOperation` Concurrency Reference ([R3-010])

| `AwaitOperation` | Behavior | When to Use in Percolator |
| :--- | :--- | :--- |
| **`Drop`** | Ignores new incoming triggers while an async task is already in progress. | **`ReloadCoordinator`**: Coalescing bursts of database reload events into a single roundtrip. |
| **`Switch`** | Cancels in-flight task's `CancellationToken` immediately when a new value arrives. | **Search Autocomplete**: Aborting obsolete candidate queries when user types a new character. |
| **`Sequential`** | Queues values in memory; executes one task at a time in strict FIFO order. | **Outbox Cryptography**: Serialized envelope encryption and disk staging. |
| **`Parallel`** | Executes all tasks concurrently without ordering guarantees. | **Swarm Multi-Stream Chunks**: Concurrent chunk fetches from multiple independent peers. |
