# System Context: R3, Domain & Persistence Architecture

**Core Paradigm:** The Domain is thread-agnostic and mutable. State is pushed reactively via R3. Services are pure singleton orchestrators. ViewModels own the UI Dispatcher. Repositories handle stateless I/O.

## 1. Domain Models & Services (The "Pure Service" Pattern)
* **Models (Pure Domain):** Use `ReactiveProperty<T>`, `ObservableList<T>`, and `ObservableDictionary<TKey, TValue>`.
  * *Constraint:* Models **must not** contain WPF bindings (`BindableReactiveProperty`) or know about persistence/UI threads.
* **Services (Source of Truth):** Singleton orchestrators that own the canonical observable collections.
  * *Constraint:* Expose state strictly as `IReadOnlyObservableList<T>` or `IReadOnlyObservableDictionary<TKey, TValue>`.
  * *Constraint:* Services **do not filter or sort** collections. That is a presentation concern.
  * *The UI-Agnostic Mandate:* **Never** inject `IUiDispatcher` into a Service. Services mutate state directly on background threads (e.g., inside gRPC handlers), protected strictly by Domain locks (`_peerGate`, `_relayGate`).

## 2. WPF Thread Bridging (The ViewModel's Responsibility)
Because Services freely mutate collections on background threads, the ViewModels MUST safely marshal these reactive streams to the UI thread, or WPF will throw a `NotSupportedException`.

* **Bridging Collections (`ObservableList<T>`):**
  Cysharp's `CreateView()` executes synchronously on the background thread. You must cross the UI boundary at the adapter level using `SynchronizationContextCollectionEventDispatcher`.
  ```csharp
  // 1. Create the view (Happens on background thread)
  _publishedToView = _state.Relationships.CreateView(rel => ...).AddTo(ref _bag);
  
  // 2. Marshal the collection events to WPF Dispatcher
  PublishedToTags = _publishedToView
      .ToNotifyCollectionChanged(SynchronizationContextCollectionEventDispatcher.Current)
      .AddTo(ref _bag);
  ```

* **Bridging Properties (`Observable<T>`):**
  When projecting singular values to the UI, you must marshal the stream *before* converting it to a Bindable property.
  ```csharp
  model.Property.DistinctUntilChanged()
       .ObserveOnCurrentSynchronizationContext() // Marshal to WPF
       .ToBindableReactiveProperty()
       .AddTo(ref _bag);
  ```

## 3. Concurrency & Locking Constraints
* **The Race Condition Trap:** `ObservableCollections` mutate immediately on the calling thread. If a background thread reads/iterates a collection (e.g., during a Save trigger) while another thread calls `.Add()`, the app will crash with `InvalidOperationException`.
  * *Mandate:* You must wrap **both** mutations and snapshot iterations in the exact same `SemaphoreSlim` lock.
* **Sync-over-Async Starvation:** In high-throughput gRPC/Network methods, **never** use `SemaphoreSlim.Wait()`. You must always use `await _gate.WaitAsync(ct).ConfigureAwait(false)` to prevent ThreadPool starvation.

## 4. Persistence Ignorance & The "Domain Snapshot" Pattern
Services must never know about DTOs or JSON. Passing live Domain Models to a background repository thread causes crashes if network traffic mutates the live collections during JSON serialization.

* **The Mandate:** Implement the **Domain Snapshot Pattern**.
  1. Domain models must implement a synchronous `.Freeze()` method that deep-copies current state into pure, immutable `record` types.
  2. The Service holds the domain lock (`_peerGate`) *only* long enough to call `.Freeze()` and snapshot the collections.
  3. The immutable records are passed to the Repository, which safely maps them to DTOs and performs slow disk I/O on a background thread without locking the domain.

* **Debounced Save Trigger Example:** Use a unified `Subject<Unit>` to collapse rapid mutations.
  ```csharp
  _saveTrigger.Debounce(TimeSpan.FromMilliseconds(250))
      .SelectAwait(async (_, ct) => {
          // MUST lock over the entire snapshot iteration
          await _gate.WaitAsync(ct).ConfigureAwait(false);
          try { 
              var peers = _peers.Select(m => m.Freeze()).ToList(); 
              var rels = _relationships.Select(r => r.Freeze()).ToList();
              return new SimulatorStateSnapshot(peers, rels); 
          }
          finally { _gate.Release(); }
      })
      .SubscribeAwait(async (snapshot, ct) => await _repo.SaveStateAsync(snapshot, ct).ConfigureAwait(false), AwaitOperation.Sequential);
  ```

## 5. R3 & ObservableCollections Traps
* **The `.Values` Trap:** Cysharp's `ObservableDictionary` uses explicit interface implementations. `dict.Values` causes compiler errors. **Always use** `dict.Select(kvp => kvp.Value)`.
* **Live Collection Mutation:** `ObservableCollections` return lazy enumerables. If a background loop orchestrates a `foreach` and removes items, it will throw. Materialize an array first: `var snapshot = dict.Select(x => x.Value).ToArray(); foreach(var item in snapshot) { dict.Remove(item.Id); }`
  * Prefer to create views from ObservableCollections over enumerating their members
