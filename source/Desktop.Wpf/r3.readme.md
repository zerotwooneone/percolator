# System Context: R3, Domain & Persistence Architecture

**Core Paradigm:** The Domain is thread-agnostic and mutable. State is pushed reactively via R3. Services are singleton orchestrators. Repositories handle stateless I/O.

## 1. Domain Models & Services
* **Models (Pure Domain):** Use `ReactiveProperty<T>`, `ObservableList<T>`, and `ObservableDictionary<TKey, TValue>`.
  * *Constraint:* Models **must not** contain WPF bindings (`BindableReactiveProperty`) or know about persistence/UI threads.
* **Services (Source of Truth):** Singleton orchestrators that own the canonical observable collections.
  * *Constraint:* Expose state strictly as `IReadOnlyObservableList<T>` or `IReadOnlyObservableDictionary<TKey, TValue>`.
  * *Constraint:* Services **do not filter or sort** collections. That is a presentation concern.
  * *Constraint:* Track lifecycle via root dictionaries (e.g., `Dictionary<Guid, IDisposable> _runtimePersistenceById`). Do **not** create separate dictionaries for toggleable boolean features; attach them to the root `CompositeDisposable` lifecycle.

## 2. R3 & ObservableCollections Traps
* **The `.Values` Trap:** Cysharp's `ObservableDictionary` uses explicit interface implementations. `dict.Values` causes compiler errors. **Always use** `dict.Select(kvp => kvp.Value)`.
* **Live Collection Mutation:** `ObservableCollections` return lazy enumerables. If a background loop orchestrates a `foreach` and removes items, it will throw `InvalidOperationException: Collection was modified`.
  * *Fix:* Materialize an array first: `var snapshot = dict.Select(x => x.Value).ToArray(); foreach(var item in snapshot) { dict.Remove(item.Id); }`

## 3. Concurrency (Critical Constraints)
* **Sync-over-Async Starvation:** In high-throughput gRPC/Network methods, **never** use `SemaphoreSlim.Wait()`. You must always use `await _gate.WaitAsync(ct).ConfigureAwait(false)` to prevent ThreadPool starvation.

## 4. Persistence Ignorance & The "Domain Snapshot" Pattern
Services must never know about DTOs or JSON. Passing live Domain Models (which contain inner `ObservableCollections`) to a background repository thread causes crashes if network traffic mutates the live collections during JSON serialization.
* **The Mandate:** Implement the **Domain Snapshot Pattern**.
  1. Domain models must implement a synchronous `.Freeze()` method that deep-copies current state into pure, immutable `record` types using standard `IReadOnlyList<T>`.
  2. The Service holds the domain lock (`_peerGate` / `_relayGate`) *only* long enough to call `.Freeze()`.
  3. The immutable records are passed down the pipeline to the Repository, which safely maps them to DTOs and performs slow disk I/O on a background thread without locking the domain.
* **Debounced Save Trigger:** Use a unified `Subject<Unit>` in the service to collapse rapid mutations into sequential disk writes.
  ```csharp
  _saveTrigger.Debounce(TimeSpan.FromMilliseconds(250))
      .SelectAwait(async (_, ct) => {
          await _gate.WaitAsync(ct).ConfigureAwait(false);
          try { return _models.Select(m => m.Freeze()).ToList(); }
          finally { _gate.Release(); }
      })
      .SubscribeAwait(async (snapshots, ct) => await _repo.SaveAsync(snapshots, ct).ConfigureAwait(false), AwaitOperation.Sequential);
  ```
* **File I/O Lock:** The repository must protect **both** writes and reads with a local `SemaphoreSlim _ioGate` to prevent `IOException` file-sharing violations.
