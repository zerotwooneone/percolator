# Percolator System Requirements

Spec: [system-requirements-spec](spec/system-requirements-spec.md)

## 1. Functional System Capabilities

1. **`SYS-ISOLATED-PERSONAS` (Cryptographically Isolated Local Personas):** `[Verify: Integration]` The system shall allow the user to generate, switch between, and permanently delete independent cryptographic personas locally, ensuring separate personas share zero cryptographic keys, session states, or network identifiers (realizes [`UN-PERSONAS`](UserNeeds.md#1-core-functional-needs)).
2. **`SYS-MULTI-DEVICE-SYNC` (Authorized Multi-Device State Synchronization):** `[Verify: Simulation]` The system shall allow a user to authorize multiple personal devices under a single identity and synchronize contact trust states, conversation histories, and membership updates across all authorized devices of that identity (realizes [`UN-MULTI-DEVICE`](UserNeeds.md#1-core-functional-needs)).
3. **`SYS-DEVICE-REVOCATION` (Authorized Device Revocation):** `[Verify: Simulation]` `[Control: Protective]` The system shall allow a user to revoke an authorized device from their identity such that peer sessions and sibling devices cease trusting or encrypting subsequent communications to the revoked device (realizes [`UN-MULTI-DEVICE`](UserNeeds.md#1-core-functional-needs); mitigates [`HAZ-COMPROMISED-SECONDARY-DEVICE`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
4. **`SYS-PAIRWISE-CONVERSATIONS` (Authenticated Direct Messaging):** `[Verify: Simulation]` The system shall establish mutually authenticated, end-to-end encrypted one-to-one communication sessions between peers and present messages in deterministic causal order across participating devices (realizes [`UN-CONVERSATIONS`](UserNeeds.md#1-core-functional-needs)).
5. **`SYS-CONTACT-CONSENT-GATE` (Pending-Consent Staging for Unknown Peers):** `[Verify: Integration]` `[Control: Protective]` Inbound connection requests from unknown identities shall be staged locally in a pending-consent state without emitting network receipts or establishing an active conversation until explicitly approved by the user (realizes [`UN-CONVERSATIONS`](UserNeeds.md#1-core-functional-needs); mitigates [`HAZ-PRESENCE-AND-BLOCK-ORACLE`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
6. **`SYS-GROUP-MEMBERSHIP-LIFECYCLE` (Peer-Governed Multi-Party Conversations):** `[Verify: Simulation]` The system shall support multi-party encrypted conversations where authorized participants can add and remove members directly among peers without a central server (realizes [`UN-CONVERSATIONS`](UserNeeds.md#1-core-functional-needs)). `#group-membership`
7. **`SYS-ASYNC-SESSION-INIT` (Asynchronous Session Initialization with Offline Peers):** `[Verify: Simulation]` The system shall support initiating a new end-to-end encrypted session with an offline recipient using pre-published key material hosted on untrusted relays without requiring simultaneous online presence (realizes [`UN-ASYNC-MESSAGING`](UserNeeds.md#1-core-functional-needs)). `#offline-delivery`
8. **`SYS-ASYNC-STORE-AND-FORWARD` (Offline Relay Buffering and Retrieval):** `[Verify: Simulation]` When a recipient device is offline or unreachable via a direct path, the system shall support buffering encrypted messages on untrusted relay peers and retrieving them asynchronously when the recipient reconnects (realizes [`UN-ASYNC-MESSAGING`](UserNeeds.md#1-core-functional-needs)). `#offline-delivery`
9. **`SYS-OUT-OF-BAND-VERIFICATION` (Out-of-Band Contact Verification Fingerprint):** `[Verify: Integration]` `[Control: Protective]` The system shall expose a deterministic, human-comparable verification code binding both peers' identity keys so users can verify contact authenticity out-of-band and inspect verification status (realizes [`UN-CONTACT-VERIFICATION`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs); mitigates [`HAZ-KEY-SUBSTITUTION-MITM`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
10. **`SYS-RETENTION-PURGE` (Local Deletion and Cooperative Message Expiration):** `[Verify: Integration]` The system shall irrevocably purge deleted messages, conversations, or personas from local storage upon user command, and automatically purge expired messages from local storage once a conversation's configured retention duration elapses (realizes [`UN-DATA-RETENTION`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs)). `#ephemeral-retention`

## 2. Security, Privacy, and Risk Control Invariants

1. **`SYS-RATCHETED-CONFIDENTIALITY` (Forward Secrecy and Post-Compromise Recovery):** `[Verify: Simulation]` `[Control: Inherent]` All direct and group communications shall be encrypted and authenticated end-to-end using continuously ratcheted per-message keys such that the compromise of current session state cannot decrypt prior messages, and subsequent key-agreement steps restore confidentiality for future messages (mitigates [`HAZ-SESSION-KEY-COMPROMISE`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
2. **`SYS-GROUP-REMOVAL-KEY-ROTATION` (Cryptographic Exclusion of Removed Group Members):** `[Verify: Simulation]` `[Control: Inherent]` Removing a participant from a group conversation shall rotate group encryption keys across remaining participants before any subsequent group message is transmitted, rendering the removed participant cryptographically unable to decrypt subsequent group traffic (realizes [`UN-CONVERSATIONS`](UserNeeds.md#1-core-functional-needs); mitigates [`HAZ-REMOVED-MEMBER-EAVESDROPPING`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)). `#group-membership`
3. **`SYS-KEY-CHANGE-TRUST-HALT` (Identity Key-Change Suspension and Warning):** `[Verify: Integration]` `[Control: Information]` If an established contact's cryptographic identity key changes, the system shall suspend outbound transmission to that contact and present an explicit warning requiring user acknowledgment before resuming communication (mitigates [`HAZ-KEY-SUBSTITUTION-MITM`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
4. **`SYS-RELAY-ONLY-CLOAKING` (Direct-Address Cloaking via Relay-Exclusive Routing):** `[Verify: Simulation]` `[Control: Inherent]` When direct connections are disabled globally or for a specific peer, the system shall route all handshakes and conversation traffic with that peer exclusively through untrusted relays and omit local network endpoints from all wire payloads visible to that peer (realizes [`UN-ADDRESS-PRIVACY`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs)). `#relay-privacy`
5. **`SYS-BLOCK-WIRE-INDISTINGUISHABILITY` (Silent Drop and Offline Indistinguishability for Blocked Peers):** `[Verify: Simulation]` `[Control: Inherent]` The system shall silently discard inbound traffic from a blocked identity and emit zero acknowledgments, error frames, or presence signals toward that identity, making a blocked state indistinguishable from an offline state on the wire (realizes [`UN-PEER-BLOCKING`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs); mitigates [`HAZ-PRESENCE-AND-BLOCK-ORACLE`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
6. **`SYS-PRE-ACTIVATION-STEALTH` (Zero Network Activity Prior to Identity Activation):** `[Verify: Integration]` `[Control: Inherent]` The system shall bind zero listening network sockets and transmit zero outbound network packets prior to explicit user vault unlock and persona activation (realizes [`UN-SESSION-LOCK`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs); mitigates [`HAZ-PRE-UNLOCK-NETWORK-EXPOSURE`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards)). `#session-lock`
7. **`SYS-LOCK-TEARDOWN-AND-ZEROIZATION` (Immediate Network Teardown and Memory Zeroization on Lock):** `[Verify: Integration]` `[Control: Protective]` Locking or terminating an active session shall immediately sever all network connections and cryptographically zeroize decrypted master keys, session keys, and transient plaintexts in volatile memory (realizes [`UN-SESSION-LOCK`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs); mitigates [`HAZ-POST-LOCK-MEMORY-RESIDUE`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards)). `#session-lock`
8. **`SYS-AT-REST-VAULT-ENCRYPTION` (Authenticated At-Rest Storage Encryption):** `[Verify: Integration]` `[Control: Protective]` All persistent local state—including private identity keys, session states, contact lists, and message histories—shall be encrypted and authenticated at rest using keys derived solely from user-supplied credentials so that locked storage cannot be decrypted without user credentials (mitigates [`HAZ-OFFLINE-DISK-EXTRACTION`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards)). `#session-lock`
9. **`SYS-PAYLOAD-LENGTH-PADDING` (Ciphertext Length Padding):** `[Verify: Integration]` `[Control: Protective]` Outbound application payloads shall be padded prior to encryption to obscure fine-grained message length variance on the wire (mitigates [`HAZ-CIPHERTEXT-SIZE-CORRELATION`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)). `#relay-privacy`
10. **`SYS-BLINDED-RELAY-ENVELOPES` (Sender- and Context-Blinded Relay Envelopes):** `[Verify: Simulation]` `[Control: Inherent]` Store-and-forward envelopes routed through or buffered on untrusted relays shall conceal plaintext sender identity and conversation structure from the relay node (mitigates [`HAZ-RELAY-HEADER-CORRELATION`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)). `#relay-privacy`
11. **`SYS-ATOMIC-STATE-PERSISTENCE` (Crash-Atomic Session Progression and Outbound Queuing):** `[Verify: Integration]` `[Control: Inherent]` Advancing cryptographic session state and persisting outbound messages to the local delivery queue shall execute atomically prior to network transmission so process termination or link failure cannot desynchronize session state or silently drop messages (realizes [`UN-ASYNC-MESSAGING`](UserNeeds.md#1-core-functional-needs); mitigates [`HAZ-CRASH-STATE-DESYNC`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards)). `#offline-delivery`

## 3. External Interfaces and Resource Boundaries

1. **`SYS-MUTUAL-AUTHENTICATED-WIRE-TRANSPORT` (Mutually Authenticated Encrypted Wire Transport):** `[Verify: Integration]` `[Control: Protective]` All external network communications between peers and relays shall occur over mutually authenticated, encrypted transport channels that verify peer transport credentials before processing protocol frames (mitigates [`HAZ-TRANSPORT-SPOOFING`](RiskRegister.md#1-cryptographic-identity-and-privacy-hazards)).
2. **`SYS-PRE-CRYPTO-INGRESS-PROTECTION` (Pre-Crypto Rate Limiting and Replay Rejection):** `[Verify: Simulation]` `[Control: Protective]` At the external network boundary, the system shall enforce frame size ceilings, rate limits, and replay rejection before executing asymmetric cryptographic operations or dispensing one-time pre-keys (mitigates [`HAZ-INGRESS-RESOURCE-EXHAUSTION`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards) and [`HAZ-PREKEY-POOL-STARVATION`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards)).
3. **`SYS-BOUNDED-RELAY-QUOTAS` (Zero-Administration Relay Resource Quotas):** `[Verify: Simulation]` `[Control: Protective]` When operating as a background relay for remote peers, the system shall enforce configurable ceilings on disk storage, memory, bandwidth, and per-identity mailbox/pre-key quotas, evicting expired or excess items without degrading local user operation (realizes [`UN-BOUNDED-RELAY`](UserNeeds.md#2-sovereignty-privacy-and-operational-trust-needs); mitigates [`HAZ-INGRESS-RESOURCE-EXHAUSTION`](RiskRegister.md#2-endpoint-availability-and-integrity-hazards)).
